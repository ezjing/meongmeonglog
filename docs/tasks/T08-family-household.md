# T08. 가족 — 집·초대 코드·권한·탈퇴

가족·다견 계획([docs/family-plan.md](../family-plan.md))의 3단계 앞부분. **상태: 서버 배포됨 (2026-11-24). 정책 페이지·웹·OTA 전 — 정책 시행일 결정 필요.** 결정(F1~F14, 초대 코드 값)과 문구는 2026-11-23 사용자가 모두 승인했다. 개인정보처리방침 문구 초안만 구현 전에 따로 승인받는다.

## 승인된 결정 (family-plan.md)

- 묶는 단위는 **집**. 한 사람이 여러 집에 속할 수 있고, 홈 강아지 목록에 모든 집의 강아지가 함께 나온다
- 집 관리자: 강아지 정보 수정, 강아지 추가·삭제, 가족 초대·내보내기 / 가족: 산책 기록, 일기 보기·만들기
- 초대: **초대 코드** (2026-11-23 링크에서 변경). **1회용, 7일 만료**, 집당 **최대 10명**(관리자 포함)
- 기록 삭제는 관리자와 그 산책을 기록한 사람만
- 관리자가 탈퇴할 때 가족이 있으면 **새 관리자를 직접 고른다**. 가족이 없으면 집 전체를 지운다
- 누가 탈퇴하든 그 사람의 산책 기록은 남기고 기록한 사람만 "탈퇴한 가족"으로 바꾼다
- 개인정보처리방침에 가족에게 공개되는 항목과 탈퇴 시 처리를 추가한다

## 현재 구조 (확인한 것)

- 모든 RLS가 `dogs.user_id = auth.uid()` 기준 (`006`, `009`). `dogs.user_id`는 `users`에 **on delete cascade** → 지금 관리자가 탈퇴하면 강아지·산책·일기가 전부 지워진다
- 저장소 정책은 `{uid}/…` 폴더 주인만 읽기 외 작업 가능. 산책 사진은 올린 사람 폴더(`{uid}/{walkId}/`, 원본과 `_small.jpg`), 강아지 프로필은 등록한 사람 폴더
- `delete-account` Edge Function은 그 사람 폴더의 파일을 **모두** 지운 뒤 `auth.users`를 지운다
- `users`는 본인만 읽을 수 있다 → 다른 가족의 호칭을 볼 수 없다
- `diaries-generate`는 `dog.user_id === 요청자`로 권한을 본다
- 공유 링크 함수(`008`)는 `security invoker`라 RLS만 바꾸면 따라온다
- **1.0.0 설치본은 OTA를 못 받는다.** 옛 앱은 `dogs.user_id`로 강아지를 만들고 산책을 기록한다. 옛 앱이 계속 동작해야 한다

## 구현 방향

### 1. DB 마이그레이션 `010_households.sql`

- `households(id, created_at)`
- `household_members(household_id, user_id, role('admin'|'member'), joined_at)`, (집, 사람) 유일, 집마다 관리자 1명
- `household_invites(code, household_id, created_by, created_at, expires_at, used_at, used_by)`. 코드는 서버(RPC)가 만든다. 쓰지 않았고 만료되지 않은 코드끼리 유일
- `household_invite_attempts(user_id, attempted_at, succeeded)` — 잘못 입력 제한용. 오래된 행은 정리해도 된다
- 사용자마다 자기 집(F2): 기존 사용자는 마이그레이션에서, 새 사용자는 `users` insert 트리거로
- `dogs.household_id` 추가. 기존 강아지는 주인의 집으로. **`dogs.user_id`는 남긴다**("등록한 사람", 옛 앱 호환). 옛 앱이 `user_id`만 넣으면 트리거가 그 사람의 집으로 채운다
- `dogs.user_id`의 `on delete cascade`를 **`set null`**로 바꾼다 (관리자 탈퇴 시 강아지가 지워지지 않게). 집째 지울 때는 Edge Function이 직접 지운다
- `walks.recorded_by`(기록한 사람, 기본값 `auth.uid()`, 사용자 삭제 시 `set null` = "탈퇴한 가족"). 기존 산책은 강아지 주인으로 채운다
- 권한 확인 함수 `is_household_member(household_id)`, `is_household_admin(household_id)` (`security definer`, `search_path` 고정)
- RLS 전부 교체: 강아지·산책·좌표·배변·사진·일기·`walk_dogs`·공유 링크는 **그 강아지 집의 구성원**. 강아지 수정·삭제는 관리자. 산책·일기 삭제는 관리자 또는 `recorded_by`. `users`는 같은 집 구성원이 호칭·프로필 사진만 읽을 수 있게 (F13, 별도 view 또는 RPC)
- 저장소: 산책 사진 폴더(`{uid}/{walkId}/`)는 그 산책 집의 관리자도 지울 수 있게. 강아지 프로필은 관리자가 자기 폴더에 새로 올리는 방식이라 그대로
- RPC (모두 `security definer`, 요청자 확인)
  - `create_household_invite(household_id)`: 관리자만. 코드 생성·저장 후 반환
  - `preview_household_invite(code)`: 수락 확인 화면용. 입력 제한 확인 → 코드 확인(틀리면 시도 기록) → 초대한 사람 호칭·강아지 이름·사진만 반환
  - `accept_household_invite(code)`: 입력 제한·만료·사용 여부·이미 구성원·10명 상한 확인 → 구성원 추가 → 코드 사용 처리. 한 트랜잭션
  - 내보내기·나가기
- 오류는 화면 문구로 바꿀 수 있게 구분된 코드로 돌려준다 (틀림·만료·사용됨은 화면에서 한 문구로 보인다)

### 2. Edge Functions

- `diaries-generate`: 권한을 "요청자가 그 강아지 집의 구성원"으로
- `delete-account`: 요청에 집별 새 관리자를 받는다(F11) → 관리자 넘기기 → 가족이 없는 집만 강아지·파일째 삭제 → 남는 집의 파일은 지우지 않음(F12) → 계정 삭제. 새 관리자가 빠졌거나 그 집 구성원이 아니면 아무것도 지우지 않고 실패

### 3. 앱 (앱·웹 같은 코드)

- `entities/household`(새 slice): 내 집 목록, 구성원, 초대 코드 만들기·미리보기·수락, 내보내기·나가기 API
- 강아지 목록은 내가 속한 모든 집의 강아지. 강아지 추가는 자기 집. 강아지 수정 진입 시 관리자 확인(F10)
- 가족 관리 화면(F6·F7), 초대 코드 시트(앱은 공유 시트, 웹은 복사), 코드 입력 화면 → 수락 확인 화면(F4)
- 온보딩: 강아지 등록 화면의 `초대 코드가 있어요` → 코드 입력. 가족이 되면 홈으로 (F5)
- 탈퇴 흐름(F11)
- 일기 삭제 버튼은 관리자 또는 기록한 사람에게만 보인다
