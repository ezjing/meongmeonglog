# T06. 다견 지원

가족·다견 계획([docs/family-plan.md](../family-plan.md))의 2단계. **상태: 진행 중.** 아래 결정과 문구는 2026-11-23 사용자가 모두 승인했다.

## 목표

한 사람이 강아지를 여러 마리 등록하고, 강아지를 바꿔 가며 보고, 여러 마리를 함께 데리고 산책하면 강아지마다 일기가 생긴다. 강아지가 한 마리인 사용자의 화면과 흐름은 지금과 같다.

## 승인된 범위 (family-plan.md)

- 강아지 추가: 설정 드로어의 "강아지 추가"에서 기존 등록 화면(기본 정보 → 성격)을 다시 쓴다
- 강아지 전환: 홈 위쪽 아바타 줄. 캘린더·리스트는 선택한 강아지 기준
- 산책 시작 때 데려갈 강아지를 여러 마리 고를 수 있다
- 일기는 강아지마다 따로 만든다

## 현재 구조 (확인한 것)

- DB: `dogs.user_id`라 한 사람이 여러 마리를 가질 수 있다. `walks.dog_id`는 한 마리, `walk_events.walk_id`와 `diaries.walk_id`는 유일(산책당 1개)
- 화면 6곳이 `dogs?.[0]`만 쓴다: `HomeScreen`, `SettingsScreen`, `SettingsDrawer`, `DogBasicScreen`, `DogPersonalityScreen`, `entities/dog/model/useDogName.ts`
- 강아지 등록: `dogBasic` → `dogPersonality` → `welcome`(여기서 `createDog` + 환영 인사). 수정은 같은 화면을 `mode=edit`로 연다(`openDogEdit`)
- 산책 종료 화면(`WalkFinishScreen`)의 배변 활동·친구 만남·메모는 산책당 1개(`walk_events`)
- `diaries-generate` Edge Function은 `walkId`만 받아 `walks.dogs`로 강아지를 찾고, 산책당 일기 1개를 만든다
- 일기 조회(최근·날짜별·캘린더·목록)는 강아지 구분 없이 내 일기 전부
- T05 삭제는 `walks` 행을 지운다 → 여러 마리 산책이면 다른 강아지 일기까지 지워진다
- **1.0.0 설치본은 OTA를 못 받는다.** 옛 앱은 계속 `walks.dog_id` 하나로 산책을 만들고 `walkId`만으로 일기를 요청한다. DB·Edge Function은 옛 앱이 그대로 동작하게 바꿔야 한다

## 구현 방향 (결정 승인 후 Cursor가 따를 것)

### 1. DB 마이그레이션 `009_multi_dog_walks.sql`

- `walk_dogs(walk_id, dog_id)` 연결 테이블 (기본키 둘의 조합, 둘 다 cascade). 기존 `walks`마다 `walks.dog_id`로 한 행씩 채운다
- `walks.dog_id`는 **남긴다** ("산책을 시작한 대표 강아지"). 옛 앱 호환과 기존 RLS를 위해서다. `walks`에 insert될 때 `walk_dogs`에 대표 강아지 행을 자동으로 넣는 트리거를 둔다
- `walk_events`: `dog_id` 추가, 기존 행은 `walks.dog_id`로 채움. 유일 조건을 `walk_id` → `(walk_id, dog_id)`. 옛 앱이 `dog_id` 없이 넣으면 `walks.dog_id`로 채우는 트리거
- `diaries`: 유일 조건을 `walk_id` → `(walk_id, dog_id)`
- RLS: `walk_dogs`는 강아지 주인만. 기존 정책은 그대로 둬도 된다 (T06에서는 한 산책의 강아지가 모두 같은 사람 것이다). `walk_dogs`에 넣는 강아지가 산책 주인의 강아지인지 정책에서 확인한다
- 공유 링크 함수(`get_shared_diary` 등)가 `walk_id` 유일을 가정하는지 확인하고, 가정하면 고친다

### 2. Edge Function `diaries-generate`

- `{ walkId, dogId? }`를 받는다. `dogId`가 없으면 `walks.dog_id` (옛 앱 호환)
- `dogId`가 그 산책의 `walk_dogs`에 있고 요청한 사람의 강아지인지 확인
- 기존 일기 조회와 `walk_events` 조회를 `(walk_id, dog_id)`로 바꾼다

### 3. entities

- `entities/dog`: 선택된 강아지 store(기기 저장, D5)와 `useSelectedDog()`. `useDogDisplayName`·`useDiaryDogName`은 선택된 강아지 기준으로
- `entities/walk`: `startWalk(dogIds)`(대표 = 첫 번째, 나머지는 `walk_dogs` insert), 강아지별 `walk_events` 저장, 산책의 강아지 목록 조회. D3 삭제(`deleteDiaryFromWalk` 또는 `deleteWalk`의 분기)
- `entities/diary`: 조회 hook에 `dogId` 인자와 query key 추가. `generateDiary({ walkId, dogId })`

### 4. 화면

- 홈: 앱바에 아바타 줄(선택된 강아지 강조), 오늘 상태·최근 일기는 선택한 강아지 기준(D6), 산책 시작 바텀시트(D4)
- 캘린더·리스트: 선택한 강아지 기준. 강아지를 바꾸는 방법은 홈의 아바타 줄뿐
- 설정 드로어: `강아지 추가` → `dogBasic`(등록 모드, 온보딩 store 초기화) → `dogPersonality` → `welcome` → 홈(D8). 수정은 선택된 강아지(D9). 수정 화면은 `dogId` 파라미터로 대상 강아지를 받는다
- 산책 종료: 여러 마리면 강아지별 구역(D1)
- 일기 생성: D7
- 일기 상세 삭제: D3
- 온보딩 경로 판단(`resolveDogOnboardingRoute`)은 그대로 (0마리일 때만 등록 화면)

### 5. 하지 말 것

- `walks.dog_id` 삭제, 옛 앱이 실패하는 DB·Edge Function 변경

## 검토 (Claude, 2026-11-23)

결과: **수정 2건 (Cursor).** 사용자 결정은 2026-11-23 완료. `tsc`·`lint` 통과 확인.

### 확인한 것
- 마이그레이션 `009`: 기존 산책마다 `walk_dogs` 대표 행을 채우고, 새 산책·옛 앱의 `walk_events`는 트리거가 대표 강아지로 채운다. 유일 조건 교체, `walk_dogs` RLS(같은 사람의 강아지만 연결)가 지시서대로다
- 옛 앱 호환: 옛 앱의 `walk_events` 저장은 `onConflict` 없는 upsert라 새 유일 조건과 충돌하지 않는다. 옛 Edge Function도 새 DB에서 `walk_events`를 배열로 받아 첫 행을 쓰므로 동작한다
- `diaries-generate`: `dogId`가 없으면 대표 강아지. 그 산책에 연결된 내 강아지인지 확인한 뒤 `(walk_id, dog_id)`로 기존 일기·배변 기록을 찾는다
- 대표 강아지 순서(`orderWalkDogs`), 2마리 이상 제목·버튼, 10마리 토스트, 강아지별 배변 구역, 강아지별 일기 생성·다시 시도, 일기 하나 삭제 시 마지막이면 산책 전체 삭제가 승인본과 같다

- 지금 앱(OTA `c98bca8b`)은 `walkId`만 보내므로 새 함수가 대표 강아지로 처리한다. 코드상으로는 정상 동작해야 하지만 실기기로 확인하지 않았다. 일기 생성을 한 번 해 보는 것을 권한다

### 수정 지시
1. **(안전장치) 홈에서 다른 강아지를 고르면 진행 중인 산책 카드가 안 보인다.** 보통 흐름에서는 산책 중에 홈으로 올 수 없다 (산책 중·종료 화면의 뒤로가기는 확인 창, 앱을 다시 열면 산책 화면으로 이동). 그래도 홈에 오게 되면 이 카드가 이어 가기로 들어가는 유일한 길이고, 카드 없이 `산책 시작`을 누르면 진행 중 산책의 위치 기록이 멈추고 끝나지 않은 `walks` 행이 남는다. 드문 경우지만 사용자 결정으로 고친다
   - 수정: 오늘 상태 카드는 **선택한 강아지와 관계없이** 진행 중인 산책이 있으면 "산책 진행 중이에요"를 보여 준다 (`getTodayWalkStatus(activeWalk, …)`로 되돌림). 산책 중이 아닐 때의 "오늘 산책 n번"은 선택한 강아지 기준 그대로
2. 홈 아바타 줄의 선택 테두리를 `colors.primary` → `colors.primaryFg`로 (아래 결정 5)
