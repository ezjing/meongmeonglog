# T15. 여러 마리 일기: 사진은 한 번만 AI에 보내기

## 결정 (사용자 승인, 2026-11-25): C안

지금은 강아지마다 `diaries-generate`를 차례로 부르고, 매번 같은 산책 사진(첫 장의 `_small` 사본)과 긴 안내문을 Groq에 보낸다.
그래서 3마리면 15~30초가 걸리고, 무료 요금제의 분당 처리량 제한 때문에 2~3번째 강아지에서 429가 자주 난다.

C안: 강아지가 **2마리 이상인 산책**은 사진을 **한 번만** AI에 보여 주고 장면 설명(글)을 저장한다. 강아지별 일기는 사진 대신 그 설명을 넣어 **글만** 보낸다.
**강아지 1마리 산책은 지금과 똑같다** (사진을 바로 보냄).

```
지금:  [사진+강아지1] [사진+강아지2] [사진+강아지3]
C안:   [사진 → 장면 설명 저장] [설명+강아지1] [설명+강아지2] [설명+강아지3]
```

## 정해진 값 (사용자 승인, 2026-11-25)

아래 값 그대로 구현한다.

| 항목 | 값 |
|---|---|
| 저장 위치 | `walks.photo_description text null` (새 마이그레이션). 산책을 지우면 같이 지워진다 |
| 설명 길이 | 2~4문장, 응답 최대 300 토큰 |
| 설명 지시문 | "산책 사진을 일기 작성용으로 객관적으로 묘사한다: 장소, 날씨·빛, 계절감, 강아지 수·모습·행동. 사람 얼굴·차량 번호·간판 글자 등 개인을 알아볼 수 있는 정보는 쓰지 않는다. 사진에 없는 내용은 지어내지 않는다." |
| 사진 장수 | 지금처럼 첫 장 1장 |

## 할 일

### A. DB

- 마이그레이션(T11·T14 다음 번호): `alter table public.walks add column if not exists photo_description text;`
- RLS 변경 없음 (서버가 service role로 쓴다). 앱은 이 칸을 읽지 않는다

### B. Edge Function `diaries-generate`

1. 그 산책의 `walk_dogs` 수를 센다 (이미 조회하는 것이 있으면 재사용)
2. **1마리**: 지금 그대로 (`imageUrl` 전달)
3. **2마리 이상**:
   - `walks.photo_description`이 있으면 그것을 쓴다
   - 없고 사진이 있으면 Groq에 사진 + 설명 지시문으로 한 번 요청해 설명을 받고, `update walks set photo_description = ... where id = walkId and photo_description is null`로 저장한다 (동시에 두 요청이 와도 먼저 저장된 것을 쓴다. 저장 후 다시 읽어 그 값을 사용)
   - 사진이 없으면 설명 없이 진행 (지금과 같음)
   - 일기 요청은 `imageUrl` 없이 보내고, `buildDiaryUserPrompt`에 "산책 사진 설명: …" 항목을 추가해 넣는다 (`_shared/speechStyle.ts`). 사진을 볼 때 쓰던 `buildDiaryImagePrompt`의 의도(사진 속 장면을 일기에 녹이기)가 설명에도 적용되게 문장을 맞춘다. **일기 지시문의 다른 내용은 바꾸지 않는다**
4. `_shared/groq.ts`의 `generateGroqContent`에 `maxTokens` 옵션을 추가해 설명 요청에만 300을 쓴다 (기본 800 유지)
5. 설명 요청이 실패(429 포함)하면: 지금의 재시도 규칙 그대로 한 번 더, 그래도 실패하면 **사진 없이 글만으로 일기를 계속 만든다** (일기 생성 자체를 실패시키지 않는다)

### C. 클라이언트 (작게)

- `src/pages/diary-generate/ui/DiaryGenerateScreen.tsx`: 차례로 생성하는 방식은 유지한다
- 일기가 하나 만들어질 때마다 홈·목록·캘린더를 새로 고치던 것을 **모든 강아지가 끝난 뒤 한 번만** 하도록 바꾼다 (`useGenerateDiary`의 onSuccess 새로 고침을 배치 끝으로 옮기거나 옵션으로 끔). 다시 시도(retry) 한 건은 그 건 끝에 새로 고침
- 화면 문구 변경 없음

  - 여러 마리 화면은 강아지를 차례로 만들고, 홈·목록·달력 새로 고침은 전부 끝난 뒤 한 번이다. 다시 시도가 성공하면 그 건 끝에 새로 고친다. 1마리는 예전처럼 성공 직후 새로 고친다
  - 각 커밋 전에 `npm run verify` 통과
  - 개인정보처리방침에는 일기 생성을 위해 사진을 처리한다는 문장과, 사진에서 만든 설명 글을 저장한다는 내용이 없다. 문구는 바꾸지 않고 사용자에게 알렸다
- 확인하지 못한 것:
  - 마이그레이션 적용과 함수 배포 뒤의 실제 2~3마리 생성 시간, 429 여부. 배포는 하지 않았다
  - 같은 산책에 설명 요청이 동시에 두 번 들어왔을 때 먼저 저장된 글이 쓰이는지 (코드 경로만 맞춤)
